# 水下考古出水交接

直接打开 `index.html` 使用。在沉船平面图上登记标记，为每个标记挂出水交接单，
判定通过后由与登记人不同的复核人入库。

## 业务规则

- 每个标记只挂一张未结束交接单，登记：潜次、袋号、保存措施、接手人、登记人。
- 判定为待处理（异常页）的情形：同一袋号已被先登记的单占用、任一字段空白、
  登记潜次与标记的出水潜次不符；无异常的单进入待交接。
- 补录/删改照片或更正类型（含出水潜次更正）后，该标记未结束的交接单自动失效，
  并按新资料重新判定，全过程留历史记录。
- 复核人不能与登记人同一人；复核通过的单入库。入库后标记不再出现在待交接页。
- 右侧按潜次分组看待交接、异常、入库三页；潜次/类型筛选同时作用于地图与列表，
  导出 JSON 只包含当前页签与筛选下的记录。

## 文件划分

- `index.html`：页面结构与样式。
- `js/map.js`：地图业务——平面图标记渲染、状态圆点、落点坐标。
- `js/judge.js`：判定业务——提交判定、资料变更重判、复核入库。
- `js/archive.js`：存档业务——localStorage 持久化、种子数据、JSON 导出。
- `js/app.js`：页面装配，串联以上三个业务文件。

数据保存在浏览器 localStorage（`zfl30Marks` / `zfl30Handovers`），
照片经压缩后以内嵌方式存储。
